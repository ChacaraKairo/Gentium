# Design System

Versão: 1.0

Autor: Kairo Chácara

---

# 1. Introdução

O Design System do Gentium estabelece os padrões visuais e de interação utilizados em toda a plataforma.

Seu objetivo é garantir consistência, acessibilidade e facilidade de manutenção, permitindo que todas as telas compartilhem a mesma identidade visual.

---

# 2. Objetivos

O Design System deverá:

- Padronizar a interface.
- Facilitar a criação de novas telas.
- Melhorar a experiência do usuário.
- Garantir acessibilidade.
- Reduzir inconsistências.
- Facilitar manutenção.

---

# 3. Princípios

O Gentium deverá transmitir:

- Simplicidade.
- Organização.
- Serenidade.
- Clareza.
- Elegância.
- Leitura confortável.

O aplicativo deverá evitar excesso de elementos visuais.

A Bíblia deverá permanecer como elemento central.

---

# 4. Identidade Visual

A identidade visual será baseada em:

- Cores neutras.
- Alto contraste.
- Tipografia legível.
- Ícones simples.
- Poucas distrações.

---

# 5. Paleta de Cores

Categorias:

- Cor Primária.
- Cor Secundária.
- Cor de Destaque.
- Cor de Sucesso.
- Cor de Atenção.
- Cor de Erro.
- Cor de Informação.

Cada cor possuirá versões para:

- Tema Claro.
- Tema Escuro.

---

# 6. Tipografia

Toda a aplicação utilizará a mesma família tipográfica.

Categorias:

- Título Principal.
- Título Secundário.
- Cabeçalhos.
- Corpo.
- Legendas.
- Botões.
- Campos.

A leitura bíblica deverá priorizar conforto visual.

---

# 7. Espaçamentos

Será utilizada uma escala fixa.

Exemplo:

- XS
- SM
- MD
- LG
- XL
- XXL

Todos os componentes deverão utilizar essa escala.

---

# 8. Bordas

Componentes utilizarão arredondamento padronizado.

Exemplos:

- Pequeno.
- Médio.
- Grande.

---

# 9. Sombras

Sombras serão utilizadas apenas quando necessárias.

Objetivos:

- Destacar cartões.
- Destacar menus.
- Destacar diálogos.

---

# 10. Ícones

Os ícones deverão:

- Ser simples.
- Possuir significado claro.
- Manter tamanho padronizado.
- Utilizar a mesma biblioteca.

---

# 11. Componentes

O Design System deverá possuir componentes reutilizáveis.

Entre eles:

- Botão.
- Campo de texto.
- Card.
- Modal.
- Snackbar.
- Dialog.
- Badge.
- Avatar.
- Divider.
- Tabs.
- Bottom Sheet.
- Progress Bar.
- Checkbox.
- Radio Button.
- Switch.

---

# 12. Componentes Bíblicos

Componentes específicos do Gentium.

- Cartão de Versículo.
- Referência Bíblica.
- Marcador de Versículo.
- Nota.
- Estudo.
- Plano de Leitura.
- Progresso Diário.
- Sequência.
- Conquista.

---

# 13. Feedback Visual

O sistema deverá fornecer feedback para:

- Carregamento.
- Sucesso.
- Erro.
- Aviso.
- Informação.

---

# 14. Animações

As animações deverão ser discretas.

Objetivos:

- Melhorar navegação.
- Guiar atenção.
- Não distrair o usuário.

---

# 15. Responsividade

O Design System deverá funcionar em diferentes tamanhos de tela.

Prioridades:

- Celulares pequenos.
- Celulares grandes.
- Tablets.

---

# 16. Acessibilidade

O Design System deverá seguir boas práticas de acessibilidade.

Incluindo:

- Alto contraste.
- Fontes ajustáveis.
- Área mínima para toque.
- Compatibilidade com leitores de tela.
- Navegação intuitiva.

---

# 17. Modo Claro e Escuro

Todos os componentes deverão possuir versões para:

- Light Theme.
- Dark Theme.

Nenhum componente poderá existir apenas em um tema.

---

# 18. Organização

Todos os componentes visuais deverão ficar centralizados em um único módulo.

Exemplo:

shared/
└── components/

---

# 19. Evolução

Novos componentes deverão seguir os padrões definidos neste documento.

Nenhum componente poderá ser criado sem respeitar o Design System.

---

# 20. Considerações Finais

O Design System do Gentium tem como objetivo garantir uma experiência consistente, agradável e acessível.

Toda a evolução visual do projeto deverá respeitar este documento, assegurando que novos módulos mantenham a identidade visual da plataforma.
