# Plano de Desenvolvimento por Versões — Gentium

**Versão:** 1.0
**Autor:** Kairo Chácara
**Objetivo:** Guiar o desenvolvimento do Gentium com Codex até o MVP Ideal v1.4.0.

---

# 1. Estratégia Geral

O Gentium será desenvolvido em versões incrementais.

Cada versão deverá:

- entregar funcionalidades completas;
- manter o aplicativo executável;
- evitar código quebrado;
- atualizar documentação;
- possuir testes básicos;
- preservar a arquitetura modular.

A versão **v1.4.0** será tratada como o **MVP Ideal**, pronta para publicação sólida na Play Store.

# 16. Regras para o Codex

Antes de implementar qualquer versão, o Codex deverá:

1. Ler a documentação correspondente.
2. Criar ou atualizar os arquivos necessários.
3. Manter a arquitetura modular.
4. Evitar criar código duplicado.
5. Utilizar componentes do UI Kit.
6. Garantir compatibilidade com tema claro e escuro.
7. Manter o app executável.
8. Atualizar documentação quando necessário.
9. Criar testes básicos quando possível.
10. Não implementar funcionalidades de versões futuras sem autorização.

---

# 17. Ordem Recomendada de Desenvolvimento

Para cada versão:

```text
1. Revisar documentação
2. Criar estrutura de arquivos
3. Criar banco/migrations
4. Criar repositories
5. Criar services
6. Criar stores/hooks
7. Criar telas
8. Integrar navegação
9. Aplicar UI Kit
10. Testar fluxo
11. Corrigir erros
12. Atualizar documentação
```

---

# 18. Considerações Finais

O desenvolvimento do Gentium deverá priorizar estabilidade, organização e evolução gradual.

A v1.4.0 será considerada o MVP Ideal do projeto, reunindo todos os recursos essenciais para que o aplicativo seja lançado com qualidade, identidade própria e forte valor para o usuário.
